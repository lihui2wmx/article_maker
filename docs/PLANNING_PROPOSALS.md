# Bounded Research-Planning Proposals

## Purpose

Phase 6C converts explicit structural gaps in audited repository state into deterministic candidate `PlanningTask` objects. Proposal construction is advisory only: it does not persist, accept, schedule, execute, or scientifically approve work.

## Source-state gate

`PlanningProposalBuilder.propose_from_repository()` first runs the relevant repository audits for Claim/Evidence, literature, experiment, and PlanningTask state. Any audit finding blocks proposal construction. The builder never repairs invalid source state as a side effect.

`propose_from_state()` is the pure deterministic core and assumes its inputs have already crossed the appropriate audit boundary.

## Initial deterministic rules

Phase 6C intentionally starts with objective structural gaps rather than model judgment:

1. An active (`candidate` or `approved`) Claim with no persisted `ClaimEvidenceLink` produces an `evidence_review` proposal.
2. A Citation with no persisted `LiteratureNote` produces a `literature_analysis` proposal.
3. An Experiment with no completed `ExperimentRun` produces an `experiment_execution` proposal.

Rejected or superseded Claims are excluded from new evidence-review proposals. Existing deterministic PlanningTask IDs suppress duplicate proposals.

These rules identify missing structure only. They do not assert that evidence is scientifically sufficient or insufficient, that a literature source is novel, or that an experiment should actually be run.

## Determinism and provenance

Proposal IDs are stable hashes of `(proposal_reason, source_id)` and use the canonical `ptask-*` namespace. Every proposed task includes:

- explicit objective and completion criteria;
- constraints and non-goals where authority boundaries matter;
- an attributed rule-based proposer;
- priority and rationale;
- typed canonical source references;
- `proposal_reason` and `source_id` metadata.

The returned candidates are sorted deterministically.

## Human authority

Experiment-execution proposals are always created with:

- `status=proposed`;
- `authorization_requirement=human`;
- no `governing_decision_id`.

They therefore cannot become execution-eligible without a later human Decision under the Phase 6A/6B contract.

No proposal generated by this phase approves a Claim, accepts a Hypothesis, interprets ambiguous Evidence, establishes novelty, changes research direction, approves manuscript content, selects a venue, or authorizes submission.

## Non-goals

Phase 6C does not introduce:

- automatic PlanningTask persistence or acceptance;
- scheduling or workers;
- autonomous agent loops;
- experiment execution;
- provider-specific orchestration;
- probabilistic gap judgment;
- automatic scientific approval;
- manuscript generation or submission automation.
